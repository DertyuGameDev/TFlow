# ТФлоу 0.3: Django + React

## Разработка

```bash
npm ci
npm run setup
npm run dev
```

`setup` создаёт `.venv`, устанавливает зафиксированные Python-зависимости и применяет миграции без демо-наполнения и автоматического импорта. `dev` запускает Django на 8000 и Vite на 5173. Node используется для разработки/сборки frontend; все API, доступ и бизнес-операции выполняются в Django.

Данные: `backend/data/tflow.sqlite3` (игнорируется Git). Для аккаунтов используйте обычную регистрацию или управление паролями Django. Демо-аккаунты и шаблонные события удалены.

Для демонстрации `npm run dev` включает `TFLOW_DEMO_MODE=1`: можно зарегистрироваться с коротким именем, без фамилии и с простым паролем, например `1` (подтверждение должно совпадать). Интересы необязательны и свёрнуты. `TFLOW_DEMO_MODE=0 npm run dev` возвращает обычные требования к паролям. На Vercel и при `DJANGO_DEBUG=0` упрощение паролей не действует. Проверки email, прав доступа и расписания сохраняются.

В календаре доступны регистрации, личные активности, лист ожидания и экспорт в `.ics`. В программе события есть поиск, фильтры по дню/аудитории и предупреждения о пересечениях. Очередь автоматически заполняет освободившиеся места с уведомлением; вступление регистрирует пользователя на событие. В профиле нажмите «Изменить фото», чтобы загрузить или удалить аватарку (JPG/PNG/WebP, до 5 МБ и 16 Мп).

Светлая и тёмная темы переключаются кнопкой солнца/луны в шапке и на странице входа. При первом открытии используется тема устройства; ручной выбор сохраняется в браузере и применяется также к регистрации.

Ручной импорт внешнего экспортированного SQLite:

```bash
.venv/bin/python backend/manage.py import_d1 /absolute/path/to/old.sqlite
```

Скрипт работает со снимком, не изменяет исходный файл, не перезаписывает существующие строки и проверяет согласованность расписания перед фиксацией транзакции. Экспорт live D1 не выполняется автоматически.

## Production

Django обслуживает также `dist/index.html`, собранные JS/CSS и страницы входа/регистрации. Node в runtime не нужен. Переменные окружения перечислены в `backend/.env.example`; они передаются окружением процесса/хостинга, файл сам по себе не подгружается.

```bash
npm run build
.venv/bin/python backend/manage.py collectstatic --noinput
# Установить DJANGO_DEBUG=0, DJANGO_SECRET_KEY, DJANGO_ALLOWED_HOSTS и HTTPS proxy settings.
# В корне tflow:
.venv/bin/python backend/entrypoint.py
```

`entrypoint.py` применяет миграции и запускает Gunicorn на порту `PORT` (по умолчанию 8000). Внешний reverse proxy должен предоставлять HTTPS. `DJANGO_TRUST_PROXY=1` допустим только если доверенный proxy перезаписывает `X-Forwarded-Proto`.

SQLite сохраняется в `backend/data`; для нескольких реплик сервера используйте общий PostgreSQL через `DATABASE_URL`. Для SQLite нельзя запускать независимые реплики с отдельными файлами данных и ожидать единого расписания.

### Docker

```bash
docker build -t tflow .
# Передать свои переменные через environment/secret manager:
docker run --env-file /path/to/runtime.env -p 8000:8000 -v tflow-data:/app/backend/data tflow
```

Контейнер не содержит локальную базу, учётные записи, `.env` и секреты. Он работает без root. Dockerfile подготовлен; фактическая сборка Docker не запускалась в текущей среде.

ChatGPT Sites/Cloudflare Worker больше не является runtime этого приложения. Его несекретный манифест сохранён только как `docs/legacy-sites-hosting.json` для исторической публикации. Django опубликован на Vercel: https://tflow-one.vercel.app/. Также поддерживается обычный Python/Docker-хостинг.

### Vercel

Корень проекта: `tflow`, framework: Django, Python 3.12. Задайте `DJANGO_SECRET_KEY` и PostgreSQL `DATABASE_URL` с `sslmode=require` в окружении проекта. Локальная SQLite на Vercel запрещена. Точные домены deployment/production автоматически добавляются в Django allowed hosts и CSRF origins из системных переменных Vercel.

`scripts/build-vercel.py` собирает React с путями `/static/app/` и выполняет только миграции схемы. Vercel собирает статику Django для CDN. Деплой не очищает и не заполняет базу.

Очистка выполняется отдельно и только явно: `.venv/bin/python manage.py reset_data --yes`. Служебная строка блокировки расписания восстанавливается после очистки.

## Вебинары и клубы

Онлайн- и гибридные события поддерживают эфир внутри сайта: камера, микрофон, показ экрана и чат. Для локального LiveKit выполните `npm run setup:video`, затем `npm run dev`. Клубы доступны в основной навигации: создание, вступление, подбор по интересам и собственные события. [Запуск и требования публичного размещения](docs/webinars-and-clubs.md).

### Профиль и данные при записи

В кабинете события откройте «Данные при записи» и выберите обязательные поля профиля. Имя и почта берутся из аккаунта. Телефон, дата рождения, город, Telegram, работа, должность, образование, сайт, описание и интересы заполняются в профиле или при первой записи, где они нужны.

При записи платформа запрашивает только недостающее и одной транзакцией сохраняет профиль и билет. Проверка действует также для активностей и листов ожидания. Организатор видит переданные данные в карточке участника и при проверке QR; другим посетителям они недоступны. Снимок данных сохраняется на момент записи. Изменение требований не отменяет уже выданные билеты.

## API и новые сценарии

Если на мероприятии закончились места, участник может нажать «Встать в лист ожидания». Позиция видна на странице события, в профиле и в разделе календаря. Очередь не выдаёт билет и доступ по QR или к вебинару до получения места. Выйти можно в любой момент.

Отмена регистрации или увеличение вместимости автоматически передаёт места следующим готовым участникам по порядку вступления. Создаётся обычная регистрация, событие появляется в календаре и приходит уведомление. Неактивные аккаунты и участники без актуальных обязательных полей пропускаются с сохранением очереди; заполнение профиля запускает повторную проверку. После окончания события места не распределяются. Прямой запрос регистрации и запись на активность не позволяют обойти очередь.

API: `POST /api/events/{id}/waitlist` (при необходимости с полями анкеты) и `DELETE /api/events/{id}/waitlist`. Ответ сообщает `waitlisted` и `registered`: если место уже доступно, запись происходит сразу. Поля события `event_waitlisted`, `event_waitlist_position`, `event_waiting_count` показывают личную позицию и общее число ожидающих. Повторные запросы не создают дубли; выдача места, удаление из очереди и уведомление сохраняются одной транзакцией.

Swagger UI доступен по `/api/docs/`, спецификация OpenAPI — `/api/openapi.json`. Документация включает существующие маршруты Django, схемы полей, права и ошибки. CSS и JavaScript Swagger поставляются с Python-зависимостями и обслуживаются самим Django. Войдите в аккаунт на этом сайте: «Try it out» использует его сессию и CSRF-токен. Действия из документации изменяют данные с обычными правами текущего пользователя.

Нажатие на аватар в шапке открывает меню «Профиль» и «Выйти из аккаунта». Выход выполняется POST-запросом с CSRF-защитой.

В каталоге, сохранённых и кабинете организатора есть переключатель «Все / Активные / Завершённые». Активные — опубликованные события, время окончания которых ещё не наступило, включая будущие. Черновики видны владельцу только в состоянии «Все».

Вступление в клуб автоматически включает подписку на новые события, её можно отключить в карточке клуба. Уведомление создаётся при первой публикации встречи. Подробнее — в [описании уведомлений](docs/email-notifications.md).

При добавлении или редактировании пункта программы выберите существующую аудиторию, «Создать новую аудиторию» или «Онлайн · Вебинар внутри ТФлоу». Для первого очного пункта сразу доступны название и вместимость новой аудитории; онлайн-событие по умолчанию использует единственный онлайн-поток. Программа и аудитория сохраняются одним запросом: ошибка времени или вместимости откатывает создание обоих объектов. Новую аудиторию затем можно выбирать для остальных пунктов. Онлайн-поток может идти параллельно занятиям в очных аудиториях.
