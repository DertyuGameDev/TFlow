# Уведомления на почту

Сайт создаёт уведомление и письмо в одной транзакции. Отмена организатором, перенос, изменение программы и получение места из очереди создают отдельное письмо каждому адресату. Адреса остальных участников не попадают в письмо. Участникам не нужно ничего подключать.

Для настоящей доставки нужен почтовый сервис и адрес отправителя. Можно завести отдельный технический ящик; личный адрес владельца сайта не требуется. Без подключения сервиса сообщения видны в центре уведомлений, а письма остаются в очереди. Интерфейс не сообщает, что письмо доставлено, если SMTP не подключён.

## События клубов

Вступление в клуб включает подписку на новые встречи. В карточке клуба её можно отключить кнопкой «Вы подписаны на события» и включить обратно кнопкой «Подписаться на события», оставаясь в клубе. При первой публикации события подписчики получают уведомление со ссылкой на событие. Автор события, неактивные аккаунты и отключившие подписку его не получают. Повторная публикация не создаёт дублей; черновики не рассылаются. Выход из клуба удаляет подписку, повторное вступление включает её заново.

Уведомление о публикации сохраняется в центре уведомлений и в очереди писем в одной транзакции. Фактическая отправка писем требует настроенного сервиса и включённого обработчика. В текущем локальном окружении отправка выключена.

Изменения уже опубликованного события и его программы по-прежнему получают только записанные участники, которых затрагивает изменение. Подписка на новые встречи не заменяет эти уведомления по уже выданным билетам.

Сохранение активности без изменений и перенос на прежние время и место не создают уведомлений. Повтор того же запроса после успешного изменения также не создаёт новое письмо об этом изменении.

## Яндекс.Почта

Адрес для проекта — `support.tflow@yandex.ru`. Ящик ещё нужно зарегистрировать: запись адреса в настройках сайта сама по себе его не создаёт. Доступность имени определяет Яндекс при регистрации.

1. Создать ящик в [Яндекс.Почте](https://mail.yandex.ru/). Подтверждение телефона и восстановление доступа выполняет владелец ящика.
2. Разрешить почтовые приложения в [настройках ящика](https://mail.yandex.ru/?dpda=yes#setup/client). Создать [пароль приложения для Почты](https://id.yandex.ru/security/app-passwords). Обычный пароль аккаунта не использовать.
3. Из папки `tflow` запустить:

   ```sh
   npm run setup:mail
   ```

   Пароль вводится скрыто в терминале. Команда проверяет TLS-соединение и вход в SMTP, затем сохраняет `backend/.env.mail` с доступом только владельцу файла. Ничего не отправляет участникам и не меняет их очередь. При ошибке существующие настройки сохраняются. Для замены ранее настроенного подключения: `npm run setup:mail -- --replace`. Если выбранное имя занято, другой адрес Яндекса можно передать через `--sender`.

4. Перезапустить `npm run dev`: он загрузит настройки и запустит обработчик писем вместе с сайтом. **После запуска обработчика накопленные письма начнут отправляться.** Изменение файла требует перезапуска.

Адрес в письмах по умолчанию ведёт на локальный сайт. Для другого адреса: `npm run setup:mail -- --url https://example.com`. Команда настраивает только локальное окружение; опубликованный сайт требует отдельной настройки хостинга ниже.

Ручная настройка тоже доступна: скопировать `backend/.env.mail.example` в `backend/.env.mail`, заполнить пароль приложения и установить `NOTIFICATION_EMAIL_ENABLED=1`. Адрес отправителя должен соответствовать ящику авторизации. Файл с паролем исключён из Git; пароль не нужно присылать в чат или передавать аргументом команды.

### Ограничения бесплатного ящика

Это вариант для проверки доставки и небольшого начального объёма уведомлений, а не сервис массовых рассылок. Яндекс указывает лимит SMTP до 300 писем в сутки, может ограничить отправку раньше и прямо предупреждает, что личные ящики не предназначены для массовых и рабочих рассылок. Блокировка может продлеваться при повторных попытках. [Ограничения Яндекса](https://www.yandex.ru/support/yandex-360/customers/mail/ru/web/letter/create/send-many-letters).

Для постоянной рассылки большому числу участников нужен сервис транзакционных писем. Проверены бесплатные варианты на 31 октября 2026 года:

- [Resend](https://resend.com/pricing): до 3 000 писем в месяц и 100 в день, но нужен [собственный подтверждённый домен](https://resend.com/docs/dashboard/domains/introduction). Адрес `@yandex.ru` для этого не подходит.
- [SMTP2GO](https://support.smtp2go.com/hc/en-gb/articles/223087947-Free-Plan): до 1 000 писем в месяц, 200 в день, без подтверждения домена — 25 в час. Хотя отдельного отправителя можно подтвердить письмом, [для регистрации требуется рабочий адрес или свой домен](https://support.smtp2go.com/hc/en-gb/articles/12747932085145-Quick-Start-Guide).
- [Brevo](https://help.brevo.com/hc/en-us/articles/208589409-About-Brevo-s-pricing-plans): до 300 писем в день. Нужны регистрация и подтверждение отправителя; [бесплатный адрес нельзя подтвердить через DNS, технический адрес отправителя может быть заменён доменом сервиса](https://help.brevo.com/hc/en-us/articles/35852083084178-Domain-setup-for-better-email-deliverability).

Ни один из этих вариантов не подключён к производственному окружению. Регистрация и подтверждение владения отправителем не заменяются тестовыми ключами или фиктивным адресом. Для стабильной доставки лучше собственный домен и бесплатный тариф Resend; покупка домена и платные тарифы не выполнялись.

Файл `backend/.env.mail` автоматически загружается только сценарием `npm run dev`. При ручном запуске `manage.py` настройки нужно передать через переменные окружения.

Шаблон использует `smtp.yandex.ru`, SSL и порт 465. [Официальная инструкция Яндекса](https://www.yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others).

## Gmail

1. Создать аккаунт Gmail и убедиться, что выбранный адрес доступен. Регистрацию, пароль аккаунта и подтверждение телефона завершает владелец.
2. В настройках Google включить двухэтапную аутентификацию и создать отдельный [пароль приложения](https://support.google.com/accounts/answer/185833?hl=ru) для ТФлоу.
3. В локальном `backend/.env.mail` указать:

```dotenv
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USE_SSL=0
EMAIL_USE_TLS=1
EMAIL_HOST_USER=your-address@gmail.com
EMAIL_HOST_PASSWORD=
DEFAULT_FROM_EMAIL=your-address@gmail.com
NOTIFICATION_EMAIL_ENABLED=0
TFLOW_PUBLIC_URL=http://127.0.0.1:5173
```

В `EMAIL_HOST_PASSWORD` нужно локально вписать пароль приложения, а не обычный пароль Google. Значения `EMAIL_HOST_USER` и `DEFAULT_FROM_EMAIL` должны содержать реальный адрес созданного ящика. До проверки доступа отправка остаётся выключенной; затем установить `NOTIFICATION_EMAIL_ENABLED=1` и перезапустить `npm run dev`.

Пароль не передаётся в чат и не попадает в Git. На хостинге те же значения задаются через переменные окружения. Для внешнего сайта `TFLOW_PUBLIC_URL` заменяется его настоящим адресом. [Настройки сервера Gmail](https://developers.google.com/workspace/gmail/imap/imap-smtp).

## Хостинг

Настройки из шаблона передаются через переменные окружения, включая `TFLOW_PUBLIC_URL` с публичным HTTPS-адресом сайта. На сервере отдельно запускается постоянный обработчик:

```sh
python backend/manage.py send_notification_emails --watch
```

Либо планировщик периодически запускает одну порцию:

```sh
python backend/manage.py send_notification_emails --limit 25
```

Обычная функция Vercel не поддерживает постоянный процесс: для неё нужен отдельный обработчик или внешний планировщик, имеющий доступ к той же базе и SMTP-настройкам. Одного включения переменных в веб-функции недостаточно. В текущем окружении отправитель и производственный обработчик не подключены.

## Повторные попытки

Сбой SMTP сохраняет письмо для повторной попытки с увеличивающейся задержкой до часа и не откатывает отмену события. Обработчики берут задание с временной блокировкой; после аварийного завершения оно доступно снова через три минуты. Успешно отправленные задания не отправляются повторно при обычном запуске. Если процесс прервётся между приёмом письма SMTP-сервером и сохранением результата, возможен повтор — SMTP не обеспечивает доставку ровно один раз.

Автоматические тесты используют почтовый backend Django в памяти. Проверены отдельные получатели, отмена, HTML-экранирование, отсутствие личного QR в письме, сбой SMTP, повтор, блокировка заданий, откат транзакции и отсутствие писем при повторном сохранении без изменений.

Дополнительно 31 октября 2026 года проверен полный путь на отдельной базе и локальном SMTP-приёмнике: изменение события клуба → очередь → временный отказ SMTP (451) → повторная попытка → приём одного письма. Член клуба без записи на это событие не получает письмо об изменении; повторный запуск обработчика не создаёт дубль. Письмо содержит текстовую и HTML-версии. Внешние письма не отправлялись; авторизация у реального провайдера и доставка во внешний почтовый ящик без подключения сервиса не проверялись.
