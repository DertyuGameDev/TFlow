# Уведомления на почту

Сайт создаёт уведомление и письмо в одной транзакции. Отмена организатором, перенос, изменение программы и получение места из очереди создают отдельное письмо каждому адресату. Адреса остальных участников не попадают в письмо. Участникам не нужно ничего подключать.

Для настоящей доставки нужен почтовый сервис и адрес отправителя. Можно завести отдельный технический ящик; личный адрес владельца сайта не требуется. Без подключения сервиса сообщения видны в центре уведомлений, а письма остаются в очереди. Интерфейс не сообщает, что письмо доставлено, если SMTP не подключён.

## События клубов

Рассылка привязана к событию и его программе. Привязка события к клубу не добавляет всех членов клуба в получатели: письма получают участники события или активности, которых затрагивает изменение. Вступление в клуб и публикация новой встречи сами по себе не создают рассылку всем членам клуба. Отдельной функции такой рассылки сейчас нет.

Сохранение активности без изменений и перенос на прежние время и место не создают уведомлений. Повтор того же запроса после успешного изменения также не создаёт новое письмо об этом изменении.

## Яндекс.Почта

1. Подготовить технический ящик и разрешить доступ почтовым приложениям в его настройках.
2. Создать пароль приложения для почты. Обычный пароль аккаунта не использовать.
3. Локально скопировать `backend/.env.mail.example` в `backend/.env.mail`. Заполнить `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `DEFAULT_FROM_EMAIL` и установить `NOTIFICATION_EMAIL_ENABLED=1`. Адрес отправителя должен соответствовать ящику авторизации. Файл с паролем исключён из Git.
4. Перезапустить `npm run dev`: он загрузит настройки и запустит обработчик писем вместе с сайтом. Изменение файла требует перезапуска.

Файл `backend/.env.mail` автоматически загружается только сценарием `npm run dev`. При ручном запуске `manage.py` настройки нужно передать через переменные окружения.

Шаблон использует `smtp.yandex.ru`, SSL и порт 465. [Официальная инструкция Яндекса](https://www.yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others).

## Хостинг

Настройки из шаблона передаются через переменные окружения, включая `TFLOW_PUBLIC_URL` с публичным HTTPS-адресом сайта. На сервере отдельно запускается постоянный обработчик:

```sh
python backend/manage.py send_notification_emails --watch
```

Либо планировщик периодически запускает одну порцию:

```sh
python backend/manage.py send_notification_emails --limit 25
```

Обычная функция Vercel не поддерживает постоянный процесс: для неё нужен отдельный обработчик или внешний планировщик, имеющий доступ к той же базе и SMTP-настройкам. Одного включения переменных в веб-функции недостаточно. В текущем окружении отправитель и производственный обработчик не подключены.

## Повторные попытки

Сбой SMTP сохраняет письмо для повторной попытки с увеличивающейся задержкой до часа и не откатывает отмену события. Обработчики берут задание с временной блокировкой; после аварийного завершения оно доступно снова через три минуты. Успешно отправленные задания не отправляются повторно при обычном запуске. Если процесс прервётся между приёмом письма SMTP-сервером и сохранением результата, возможен повтор — SMTP не обеспечивает доставку ровно один раз.

Автоматические тесты используют почтовый backend Django в памяти. Проверены отдельные получатели, отмена, HTML-экранирование, отсутствие личного QR в письме, сбой SMTP, повтор, блокировка заданий, откат транзакции и отсутствие писем при повторном сохранении без изменений.

Дополнительно 31 октября 2026 года проверен полный путь на отдельной базе и локальном SMTP-приёмнике: изменение события клуба → очередь → временный отказ SMTP (451) → повторная попытка → приём одного письма. Незарегистрированный член клуба письмо не получает; повторный запуск обработчика не создаёт дубль. Письмо содержит текстовую и HTML-версии. Внешние письма не отправлялись; авторизация у реального провайдера и доставка во внешний почтовый ящик без подключения сервиса не проверялись.
