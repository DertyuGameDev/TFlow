# Уведомления на сайте

Email аккаунта используется для входа. Письма не отправляются: SMTP, отдельный почтовый обработчик и очередь писем удалены.

## Когда появляются сообщения

- Первая публикация события клуба: активным участникам клуба с включённой подпиской.
- Изменение программы или отмена события: затронутым участникам.
- Освободившееся место: пользователю, продвинутому из листа ожидания.
- Приближение записанной активности: напоминание через обработчик `send_activity_reminders`.

Вступление в клуб включает подписку. Её можно отключить на странице клуба. Повторная публикация не дублирует первое уведомление; участие в клубе не заменяет запись на мероприятие.

## Как проверить

Войти участником, вступить в клуб и оставить подписку включённой. Под другим аккаунтом организатора впервые опубликовать событие этого клуба. У участника появится сообщение в колокольчике и центре уведомлений. При открытом сайте список обновляется периодически, поэтому доставка не обязательно мгновенная. Закрытый сайт не показывает системный push.

`GET /api/notifications` возвращает сообщения текущего пользователя; `PATCH /api/notifications/:id` отмечает одно прочитанным, `PATCH /api/notifications` - все. Поддерживаются непрочитанные и курсорная подгрузка.

## Запуск и обновление

`npm run dev` запускает сайт и обработчик напоминаний. На сервере обработчик запускается отдельно по расписанию согласно документации мониторинга. SMTP-настройки не нужны. Старый локальный `.env.mail` больше не читается.

Перед обновлением сохраните резервную копию БД и выполните `python backend/manage.py migrate --noinput`. Миграция 0028 удаляет только старую очередь писем. Существующие уведомления, отметки прочтения, подписки и email аккаунтов сохраняются. Обратная миграция создаст пустую таблицу очереди, но не восстановит удалённые задания.

Сообщения и изменения события сохраняются в одной транзакции; отказ записи уведомлений откатывает бизнес-операцию. Исторические миграции оставлены для установки проекта с нуля.
