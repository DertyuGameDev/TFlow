# Уведомления на сайте и Web Push

Уведомления хранятся в центре уведомлений и обновляют колокольчик без перезагрузки (видимая вкладка: до 5 секунд). Пользователь включает системные push кнопкой **«Включить push»** в центре уведомлений отдельно на каждом устройстве. Разрешение браузера запрашивается только по нажатию. Есть отключение текущего устройства и кнопка **«Проверить доставку»**. Список сохраняет уже подгруженную историю при появлении новых сообщений.

## Получатели и важные действия

- Первая публикация события клуба: активные подписчики клуба с `notify_events=true`, кроме владельца. Повторная публикация не дублирует сообщение.
- Изменения события, времени и места, переносы/обмен активностей, аудитории, спикера, описания, лимита мест, требований анкеты, режима отдельной записи и новые активности: участники с билетом на событие, участники его активностей, обе очереди и подписчики клуба. Один человек получает одно сообщение об одной операции; обмен нескольких активностей объединён в одно сообщение с деталями всех изменённых пунктов. Черновики подписчикам не отправляются.
- Отмена события: те же получатели; сообщение сохраняется после удаления события и сообщает, что записи больше не действуют.
- Личные подтверждения: получение билета, запись/добавление активности в расписание, отмена, вход/выход из очереди, получение места из очереди. Повтор запроса без изменения состояния не создаёт копию подтверждения.
- Посещение: подтверждение первого QR-входа и первого настоящего подключения к видео. Загрузка плейлиста или каждого видеофрагмента не создаёт поток сообщений.
- Трансляции: начало и штатное завершение ведущим.
- Напоминания участникам с подтверждённой записью: о мероприятии за сутки, за 30 минут и в момент начала; об активности за 30 минут и в момент начала. Поздняя регистрация не создаёт запоздалое суточное напоминание. После изменения начала новое время имеет отдельный ключ; повторный запуск работника не дублирует напоминания.

Тексты содержат «было → стало», полные даты и время **по Москве**, аудиторию и другие изменённые параметры. Отключение подписки на клуб убирает его обновления, но сохраняет важные сообщения о мероприятии, на которое человек уже записан. Участие в клубе не заменяет билет.

## Доставка и конфиденциальность

Бизнес-изменение, уведомление и задания Web Push сохраняются **в одной транзакции**. Сбой записи откатывает операцию. Сетевого обращения к push-провайдеру в этой транзакции нет. Отдельный работник арендует задания, отправляет не более четырёх параллельно и повторяет временные ошибки с задержкой (до 8 попыток). После падения аренда истекает. HTTP 404/410 отключает истёкшую подписку. Статус `sent` означает принятие провайдером, не доказательство показа на экране.

Ключ VAPID хранится в постоянном закрытом файле на VM и сохраняется при каждом обновлении. Подписка и чтение уведомления требуют аккаунта, изменения — ещё и CSRF. Сервер принимает только HTTPS-адреса известных push-провайдеров, проверяет ключи и запрещает сетевые перенаправления. Endpoint и ключи устройства не возвращаются из API конфигурации и не попадают в логи.

Зашифрованный push содержит только ID уведомления. Service worker получает подробности из API под текущей сессией: чужой аккаунт их не увидит. При истечении сессии ТФлоу/ЦУ показывается общее приглашение войти без личных данных. Выход отвязывает только текущее устройство. Прочитанные сообщения и устаревшие/отменённые напоминания не отправляются из очереди. Одинаковый tag уведомления не создаёт копии при повторной доставке. Страницы и API service worker **не кэширует**.

На iPhone/iPad push доступны для сайта, добавленного на экран «Домой», на поддерживаемой версии iOS. Браузер, ОС, настройки энергосбережения и сеть могут задержать/заблокировать системный показ. Сообщения на сайте остаются доступны независимо от разрешения push. При закрытой вкладке браузер должен поддерживать фоновый Web Push. Email используется для входа; почтовая рассылка не добавлена.

## Spirit и локальный запуск

Штатный `deploy-spirit-cu` создаёт ключи **от имени tflow**, устанавливает независимый от Docker `tflow-notifications.service`, включает `TFLOW_WEB_PUSH=1` и проверяет `/api/notification-health`: `enabled=true, ready=true`. Работник запускается при загрузке VM, перезапускается после сбоя, проверяет напоминания каждые 30 секунд и имеет ограничение CPU 25% / RAM 256 МБ. При неготовности работника деплой возвращает предыдущую сборку и её конфигурацию. Защита действующих эфиров сохранена.

Локально после установки зависимостей:

```sh
python backend/manage.py migrate --noinput
python backend/manage.py setup_web_push --private backend/data/webpush-private.pem --public backend/data/webpush-public.key
TFLOW_WEB_PUSH=1 python backend/manage.py run_notification_worker
# В другом терминале: TFLOW_WEB_PUSH=1 npm run dev
```

Переменные: `TFLOW_WEB_PUSH`, `TFLOW_WEB_PUSH_PRIVATE_KEY`, `TFLOW_WEB_PUSH_PUBLIC_KEY`, `TFLOW_WEB_PUSH_SUBJECT` (HTTPS origin без завершающего слеша или mailto контакта), `TFLOW_NOTIFICATION_WORKER_ROOT`. В serverless-среде постоянный процесс не запускается сам: нужен отдельный работник с доступом к той же базе и тем же ключам. На текущем проде это systemd VM Spirit.

На этой VM стандартный маршрут к IP FCM не отвечает. `TFLOW_WEB_PUSH_GOOGLE_EDGE=1` использует DNS официального API-фронтенда Google для подключения к FCM. HTTP Host, TLS SNI и проверяемое имя сертификата остаются `fcm.googleapis.com`; проверка TLS не отключается, стороннего ретранслятора нет. Реальная отправка с VM по этому маршруту проверена ответом FCM 201.

API описан в Swagger: `/notifications`, `/notifications/summary`, `/notifications/{id}`, `/push/config`, `/push/subscriptions`, `/push/unsubscribe`, `/push/test`. Поддерживаются непрочитанные и курсорная подгрузка; личные ответы `no-store`.

Проверка: два аккаунта — организатор и участник клуба/события. Включить push участнику, закрыть вкладку; организатор переносит активность. Проверить системное сообщение с деталями, колокольчик и переход в нужный пункт программы. Дополнительно: отказ разрешения, аккаунт без подписки, повтор операции, перезапуск работника, отмена и смена времени до отправки напоминания, повторный деплой без смены ключа.

Маршрут Mozilla/Fastly также ограничен сетью VM: стандартный адрес не отвечает. `TFLOW_WEB_PUSH_MOZILLA_EDGE=1` выбирает проверенный альтернативный узел `199.232.45.91`, сохраняя Mozilla Host/SNI и обязательную проверку сертификата. Это настройка конкретной VM; при изменении маршрутов её можно выключить. У Apple часть адресов отвечает, часть зависает: короткий таймаут соединения позволяет библиотеке переходить к следующему адресу, не блокируя очередь на десятки секунд. Доступность TLS всех трёх провайдеров проверена с VM; реальная Web Push отправка проверена для Chrome/FCM.
