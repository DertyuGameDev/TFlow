# Вебинары внутри событий и клубы

## HTTPS-трансляция на Spirit

На VM можно включить `TFLOW_HTTP_BROADCAST=1` и службу
`python manage.py run_broadcast_worker`. Тогда встроенная студия передаёт
камеру, микрофон и экран короткими POST-запросами на тот же адрес сайта.
Зрители получают приватный HLS через GET; чат также использует HTTPS.
Новых публичных портов, UDP, TURN и внешнего аккаунта для этого режима нет.
Камера и микрофон изначально выключены. Это эфир одного ведущего со зрителями;
совместный видеозвонок в этом режиме не предусмотрен.

Доступ к каждому плейлисту, фрагменту и чату проверяется по аккаунту и билету
мероприятия/активности. Ключ ведущего ограничен своим онлайн-флоу и передаётся
заголовком, не ссылкой. Запрос статуса не считается посещением; получение
реального медиасегмента подтверждает его. При отзыве регистрации новые
запросы запрещаются; открытый проигрыватель регулярно перепроверяет доступ.

Браузер выбирает поддерживаемый WebM или MP4; сервер кодирует H.264/AAC.
Камера и экран переключаются без смены записываемых дорожек. При обрыве
фрагмент повторяется с тем же номером; незаметно пропустить часть видео нельзя.
Очередь ограничена, потеря связи останавливает эфир, незавершённый поток
закрывается через 30 секунд. Сохраняется только скользящий видеобуфер;
архивной записи нет. Чат ограничен 100 последними сообщениями текущей сессии.

Две локальные браузерные сессии подтвердили звук, видео 960×540, показ экрана,
чат и завершение; измеренная по метке в кадре задержка составила 8,7 секунды.
Это результат локальной проверки, а не обещание задержки на любой сети.
На VM одновременно допускаются два потока; обработчик ограничен 150% CPU
и 768 MiB памяти, чтобы не вытеснять Django. Массовая аудитория отдельно
не нагрузочно тестировалась. Vercel не запускает постоянный обработчик;
там этот режим выключен. Ниже описан сохранённый резервный режим LiveKit.

## Сценарии

У онлайн- и гибридного события есть отдельная комната вебинара по адресу `/#webinar/<id>`. Организатор публикует событие и нажимает «Открыть студию» в «Моих событиях» или в управлении событием. Зарегистрированный участник нажимает «Войти в вебинар» в карточке каталога, на странице события или в календаре. В комнате видно, начался ли эфир; подключение запускается явной кнопкой. Роли аккаунтов постоянны: зрителем может быть участник с регистрацией, ведущим — только организатор своего события. Организатор не может входить зрителем в чужие вебинары, даже по старому билету. Гостя просят войти в аккаунт с возвратом в эту комнату, а пользователя без регистрации — зарегистрироваться на событие. Внешняя ссылка и отдельный аккаунт в видеосервисе не нужны.

Только организатор события публикует камеру, микрофон и экран. У зрителей подписка на поток и чат; серверный токен не даёт им права публиковать аудио или видео. Ведущий входит с выключенными камерой и микрофоном; доступ запрашивается только по нажатию соответствующей кнопки. Ожидание разрешения на устройство не блокирует выход, чат и завершение эфира. Завершение эфира требует подтверждения и отключает всех участников. Можно начать новую сессию этого же события. Выход ведущего из комнаты останавливает его локальные дорожки; для закрытия комнаты всем нужно «Завершить эфир».

Видеопоток передаётся через LiveKit SFU. Браузер ведущего не строит отдельное соединение к каждому зрителю. Код видеоклиента загружается отдельно при открытии комнаты. Чат доставляется через надёжный канал LiveKit; в интерфейсе хранятся последние 100 сообщений текущего подключения, после выхода история не сохраняется. Запись эфира не включена.

Клуб — постоянное сообщество с категорией, описанием, создателем и участниками. Вступление в клуб не оформляет билеты автоматически. Есть поиск, категории, подборки «Все», «Мои» и «По моим интересам». У каждого клуба собственная страница событий. В каталоге можно выбрать конкретный клуб или все клубы, в которых пользователь состоит. Создатель редактирует клуб; организатор, вступивший в клуб, может связать с ним событие. Черновики видны только своему организатору.

## Локальный запуск

```sh
npm install
npm run setup
npm run setup:video
npm run dev
```

Установщик видеосервера поддерживает macOS ARM64 и Linux, проверяет SHA-256 официального архива и помещает исполняемый файл в игнорируемую папку `backend/data/tools`. Для других систем LiveKit можно установить по официальной инструкции и указать `LIVEKIT_SERVER_BINARY`. Уже установленный Homebrew LiveKit также находится автоматически.

`dev.mjs` проверяет наличие клиентской библиотеки и запускает Django, Vite и LiveKit на `127.0.0.1:7880`. Если локального LiveKit нет и внешний `LIVEKIT_URL` не задан, официальный сервер автоматически устанавливается с проверкой SHA-256; запуск сайта ожидает готовности видеосервера. При ошибке подготовки команда завершается с объяснением. Уже запущенный локальный сервер используется повторно. Используются стандартные публичные ключи LiveKit dev-режима только при `DEBUG=True`. Настоящий локальный сервер, проверенный в этой работе: LiveKit 1.13.11; браузерный SDK 2.23.0. Серверные зависимости фиксируются в `backend/requirements.lock.txt`, браузерные — в `package-lock.json`.

## Публичный хостинг

Для публичного сайта нужен LiveKit Cloud либо собственный постоянно работающий LiveKit с HTTPS/WSS и настройкой TURN для сложных сетей. В этой реализации Django-приложение и клиент могут оставаться на Vercel, а LiveKit размещается отдельным сервисом. Переменные `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` задаются на сервере; пример — `backend/.env.video.example`. Локально необязательный файл `backend/.env.video` загружается командой `npm run dev`. Настоящие секреты не входят в Git и не выдаются клиенту.

Штатный `provision-owned-video` устанавливает проверенный LiveKit 1.13.11 на vm1 и запрашивает сертификат для бесплатного технического поддомена через DNS-01. WSS работает на TCP 8080, WebRTC TCP на 8081, TURN/TLS на 8083 — в разрешённом диапазоне Spirit. Управление комнатами на самой VM использует необязательный `LIVEKIT_API_URL=http://127.0.0.1:7880`, а браузер получает публичный `LIVEKIT_URL`. API-секреты передаются через приватные переменные запуска job; в репозитории и артефактах их нет. systemd поднимает сервис после перезагрузки, certbot.timer продлевает сертификат. Успех установки сам по себе не доказывает передачу медиа между внешними сетями: для этого обязательна отдельная браузерная проверка.

Из сети vm1 HTTPS к DuckDNS завершается таймаутом. Для DNS-01 используется узкий relay `/api/internal/dns-challenge` на нашем backend Vercel: тело подписано отдельным HMAC-SHA256 секретом и имеет срок 60 секунд. Relay принимает только ACME TXT фиксированного поддомена и не позволяет выбрать другой домен, IP, URL или тип записи. `TFLOW_DUCKDNS_TOKEN` хранится только в серверном окружении Vercel; `TFLOW_DNS_HOOK_SECRET` — в Vercel и root-only конфигурации hook на VM. Это отдельная аутентификация служебного запроса; CSRF остального API остаётся включённым. Проверка подписи, ограничений запроса и ответа провайдера покрыта тестами.

Join-токен действует пять минут, привязан к случайному идентификатору конкретной сессии и роли из базы. Новый токен доступен только владельцу события или зарегистрированному участнику. Отмена регистрации запрещает следующие токены и вызывает удаление участника из комнаты. Обычный клиент дополнительно проверяет доступ каждые пять секунд. Завершение или удаление события вызывает LiveKit DeleteRoom; новая сессия получает новое имя комнаты. Сбой удаления комнаты не выдаётся за успешное завершение эфира.

Посещение онлайн-события учитывается отдельно от выдачи токена. После успешного подключения зритель вызывает `confirm` с текущей `session`; Django запрашивает LiveKit GetParticipant и проверяет личность и состояние JOINED/ACTIVE. Только такой ответ создаёт идемпотентную отметку посещения с источником `webinar`. Ошибка проверки не прерывает эфир и позволяет повторить подтверждение. QR-отметка сохраняет свой источник и проверившего организатора.

## Ленты и изменение программы

«Прямо сейчас» использует интервал `starts_at <= now < ends_at`; состояние эфира на этот фильтр не влияет. «Где был» содержит только события с подтверждённым посещением текущего пользователя, начиная с последних. Обычная регистрация и истечение времени события не считаются посещением.

Отрезок программы можно переместить целиком, сохранив длительность, или изменить его края. Клавиатурная альтернатива переносу: Alt+←/→, Shift увеличивает шаг до 15 минут. Esc отменяет жест. Для обмена выберите «Поменять местами»: сервер сначала проверяет и показывает итоговое расписание. При обмене в одной аудитории длительности и перерывы сохраняются, промежуточные пункты сдвигаются; в разных аудиториях меняется время начала, но аудитории сохраняются. Все изменения проверяются одной транзакцией, включая конфликты записанных участников. Версия программы защищает подтверждение от сохранения устаревшего предпросмотра.

В самостоятельном LiveKit уже выданный токен не отзывается мгновенно: после принудительного удаления злоумышленник с копией токена может попробовать войти до истечения его короткого срока. LiveKit Cloud имеет отдельный механизм отзыва. Истечение join-токена само по себе не обрывает уже установленное соединение. Для строгого немедленного отзыва на публичном хостинге нужно учитывать возможности выбранного развёртывания. Доступ к камере и экрану также зависит от HTTPS и разрешений браузера.

Нагрузочный тест сотен зрителей и проверка связи между разными внешними сетями не выполнялись. Максимальную аудиторию следует проверять на выбранном медиасервере и канале до массового мероприятия.

## Показ экрана и предпросмотр VS Code

Перед захватом проверяются HTTPS/localhost, наличие Screen Capture API и разрешение display-capture у родительского окна. Встроенный предпросмотр может запрещать захват; в студии есть ссылка на ту же комнату для обычного браузера, кнопка копирования и адрес для ручного переноса. Разрешение родительского окна нельзя выдать из дочерней страницы.

Захват вызывается сразу по нажатию кнопки. Экран передаётся отдельной видеодорожкой, голос — через микрофон; системный звук не запрашивается. Отмена выбора не блокирует комнату. Если ведущий вышел, пока выбирал окно, поздно полученные дорожки останавливаются; ошибка публикации также освобождает захват.

## Микрофон и индикатор речи

Включённый микрофон отмечен на кнопке; во время речи кнопка и индикатор уровня становятся зелёными. Индикация использует уровень и активность голоса, полученные от LiveKit, а не сам факт нажатия кнопки. В тишине шкала гаснет, при выключении микрофона сразу обнуляется. После разрешения доступа ведущий может выбрать другое устройство. Для зрителя показана активность голоса ведущего; если браузер блокирует воспроизведение, доступна кнопка «Включить звук». Аудиоконтекст разблокируется при входе в комнату до сетевых запросов.

## Восстановление подключения и VM

Для размещения Django и LiveKit на одной VM можно задать отдельный
`LIVEKIT_API_URL=http://127.0.0.1:7880`. Публичный `LIVEKIT_URL` остаётся WSS-адресом,
доступным компьютерам ведущего и зрителей. Серверный API не обязан обращаться
к собственному публичному адресу через NAT. Для production запрещён локальный
или незащищённый публичный адрес. Состояние комнаты сообщает причину отсутствия
конфигурации; интерфейс предлагает повторную проверку.

При start/join фоновый опрос статуса приостанавливается до завершения подключения,
чтобы старое состояние эфира не отключило ещё открывающуюся комнату. Проверки
доступа возобновляются после завершения попытки входа.

Команда `python manage.py check_webinars` проверяет конфигурацию и авторизованный
RoomService без создания/удаления комнат. Для VM подготовлен отдельный
[установщик службы и HTTPS-прокси](../deploy/spirit/README.md#вебинары-на-vm).
