# ТФлоу — соответствие EventFlow

Основа: пользовательское ТЗ EventFlow (5 страниц) и сценарии каталога/организатора Leader-ID. Фирменное оформление самостоятельное: жёлтый акцент, белый фон, спокойные серые поверхности. Промоблоки, рекламные баннеры, новости и истории отсутствуют.

| Требование | Реализация |
| --- | --- |
| Мероприятие: название, описание, даты | Кабинет организатора → создать/настроить мероприятие; черновик и публикация |
| Аудитории: имя и вместимость | Управление мероприятием → аудитории; сервер проверяет вместимость |
| Активности: описание, время, аудитория, лимит | Редактор программы; спикер необязателен |
| Программа и подробности | Каталог → мероприятие → программа; фильтр по дням |
| Авторизация | Sign in with ChatGPT; сервер получает проверенную платформой идентичность |
| Запись/отмена только своей регистрации | Сервер берёт user_id из идентичности, никогда из тела запроса |
| Дубли и полная аудитория | Составной primary key и триггер в одной атомарной операции D1 |
| Пересечения у участника | Триггер регистрации проверяет все события участника; интервалы [начало, конец) |
| Пересечения аудитории | Триггеры INSERT/UPDATE активности проверяют аудиторию и время |
| Лимит не выше вместимости | Проверяется при создании/изменении активности и уменьшении аудитории |
| Перенос с существующими регистрациями | При конфликте у любого записанного участника изменение полностью отклоняется |
| Согласованность при переносе | batch: изменение, уведомления и revision события в одной транзакции |
| Личное расписание актуально | JOIN с активностями/аудиториями; обновление каждые 20 секунд и при фокусе |
| Панель организатора | Только владелец события: программа, аудитории, участники, экспорт CSV, настройки |
| Постоянные данные | Cloudflare D1; миграции Drizzle; localStorage для записей не используется |
| Адаптивность и клавиатура | Мобильная навигация, native dialog, подписанные формы и кнопки, reduced motion |

Дополнительно: избранное, поиск и фильтры, каталог площадок, сообщества с сохранением участия, профиль и уведомления о редактировании активности. Тестовые события явно обозначены как учебные. Ожидание мест, автоматическое распределение и QR-посещаемость — дополнительные возможности ТЗ, в MVP не включены. Трансляции и платежи ТЗ не требует.

## Архитектурные решения

- Cloudflare D1 сериализует записи. Вместимость проверяется BEFORE INSERT в той же операции, которая создаёт регистрацию; схемы check-then-insert на уровне JavaScript нет.
- Соседние интервалы допускаются: конец одной активности равен началу другой.
- Перенос с конфликтом возвращает HTTP 409 и не меняет программу/уведомления. Автоматические отмены регистраций не выполняются.
- Любой вошедший пользователь может организовать своё событие. Администрировать чужое событие и читать чужой список участников запрещено на сервере.
- Hosted identity доверяется только защищённому dispatch Sites. Прямой локальный Worker предназначен для разработки и тестирования, не для публикации в обход dispatch.
- Демо-данные создаются отдельной idempotent POST-операцией после первого входа; не находятся в миграциях и не подменяют ошибки базы.
