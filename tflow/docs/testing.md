# Проверки проекта

Из папки `tflow`, после `npm ci` и `npm run setup`:

```sh
npm test                 # Все клиентские и серверные тесты
npm run test:frontend    # Логика клиента и сценарии интерфейса
npm run test:ui          # Только Vitest / Testing Library
npm run test:backend     # Django, отдельная тестовая база
npm run check           # TypeScript, включая код тестов
npm run build           # Проверка production-сборки
```

Новые зависимости тестирования устанавливаются только для разработки. Для тестов не нужны камера, физический микрофон, SMTP и запущенный LiveKit.

## Что добавлено

- Два шага создания события, обязательные поля, онлайн/гибридный формат, сохранение площадки при переключении форматов, перенос с сохранением длительности, ошибки сети и повторная отправка.
- Безопасный отказ от удаления/отмены, блокировка повторного запроса и закрытия во время операции, повтор после ошибки, клик по фону и возврат фокуса.
- Страницы уведомлений без дублей, фильтр непрочитанных, запоздалые ответы, переход после сохранения прочтения, удалённое событие и восстановление после сетевой ошибки.
- Дополнение обязательных полей анкеты без потери уже введённых значений, ошибки конкретного поля и изменение требований организатором.
- Клавиатурный выбор города, сокращения, нормализация старого значения, произвольный город, очистка и заблокированное поле.
- Вход в вебинар без автоматического доступа к устройствам, события речи, выключение и отказ микрофона, ошибка смены устройства, отключение комнаты при выходе.
- Системная/ручная тема, запрет хранилища, синхронизация вкладок, подписи переключателя и контрастный логотип приложения и страницы входа.
- Реальные обработчики запросов LiveKit: подпись серверного токена, адрес и тело запросов, таймауты, ошибки HTTP/JSON, повтор завершения, откат удаления, отзыв билета при сбое видео и смена формата после завершения.
- Команда отправки писем: лимит, отсутствие дублей, неверная настройка, отказ почтового backend, непрерывный режим и завершение по Ctrl+C. Письма остаются в тестовом хранилище Django.

## Границы автоматических проверок

Testing Library запускает реальные компоненты в jsdom и взаимодействует с полями и кнопками. В тестах комнаты LiveKit заменяется моделью событий; это проверяет состояние интерфейса и обработку ошибок, а не работу физических устройств. Серверные тесты транспортного слоя подменяют только HTTP-вызов к медиасерверу. Проверки реального потока с двумя браузерами и синтетическим звуком описаны отдельно в `verification.md`.

Для дополнительного отчёта строк покрытия сервера можно установить `coverage` в виртуальное окружение и выполнить:

```sh
.venv/bin/python -m pip install coverage
COVERAGE_FILE=/tmp/tflow.coverage .venv/bin/python -m coverage run --source=backend/flow --omit='*/migrations/*,*/tests/*' backend/manage.py test flow.tests --noinput
COVERAGE_FILE=/tmp/tflow.coverage .venv/bin/python -m coverage report
```

Не запускайте сборку одновременно с серверными тестами: Django читает ресурсы из `dist`, а Vite при сборке заменяет эту папку.
