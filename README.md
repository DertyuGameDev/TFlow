# ТФлоу

Платформа мероприятий по ТЗ EventFlow в жёлто-белом стиле референса Т Банка. Backend полностью на Python/Django, интерфейс — React/TypeScript. Каталог, программа, аудитории, регистрация на активности, личное расписание, кабинет организатора, сообщества и избранное.

## Быстрый запуск

Нужны Node.js 22.13+, Python 3.11+ и npm. Если установлен [uv](https://docs.astral.sh/uv/), настройка автоматически создаст Python 3.12 environment.

```bash
cd tflow
npm ci
npm run setup
npm run dev
```

Открыть **http://127.0.0.1:5173/**. API работает на Django: `http://127.0.0.1:8000/api/health`.

Создайте аккаунт через «Войти → Зарегистрироваться». В локальной разработке на странице входа есть «Демо-организатор» и «Демо-участник». Это явная тестовая возможность, недоступная при `DJANGO_DEBUG=0` и с нелокального адреса. Реальные пользователи входят по почте и паролю; пароли хешируются Django, запросы защищены CSRF, сессия хранится в HttpOnly cookie. Заголовки старого Sites-входа не дают прав.

`npm run setup` применяет миграции и, если найдена прежняя локальная D1, переносит её в Django. Исходная база не меняется, перед импортом создаётся согласованный SQLite-снимок. При повторном запуске записи не перезаписываются. Локальные данные, резервные копии и секреты не попадают в Git.

## Проверки

```bash
cd tflow
npm run check
npm run build
npm run test:backend
```

53 Django-теста: права, сессии, CSRF, пересечения, вместимость, отмена, переносы, избранное и профиль. Отдельные конкурентные тесты проверяют 20 попыток занять последнее место и две одновременные записи одного человека на пересекающиеся активности.

Верстка проверена в браузере на 14 ширинах от 280 до 2560 px в десяти экранах двух ролей. Сетки, поиск и кнопки перестраиваются по доступной ширине; меню сворачивается до появления переполнения. Таблица участников прокручивается внутри своего контейнера.

## Запуск собранного приложения без Node-сервера

```bash
cd tflow
npm run build
# Backend, шаблоны входа и собранный frontend обслуживает один Django:
npm start
```

Адрес: `http://127.0.0.1:5173/`. Для production используется Gunicorn/WSGI, а не `runserver`. Подробности и Docker — в [tflow/README.md](./tflow/README.md).

Историческая публикация в ChatGPT Sites содержит старую Worker-версию 0.1. Новый Django-сервер предназначен для обычного Python/Docker-хостинга: старая ссылка Sites не является адресом обновлённой версии. Актуальный локальный адрес указан выше.

## Две роли и вход по QR

- **Участник:** каталог, большая кнопка регистрации на событие, билеты и один личный QR в профиле. Запись на активности — дополнительная возможность внутри программы.
- **Организатор:** собственные события, создание короткой формой, перенос времени/площадки, список зарегистрированных и вошедших. У каждого события свой сканер.
- Сканер принимает человека только при наличии регистрации именно на выбранное событие. Повторный скан показывает существующую отметку и не увеличивает счётчик.
- QR содержит непрозрачный случайный идентификатор. Личные данные доступны самому участнику и организатору события, на которое тот зарегистрирован.

На странице `/login/` в локальной разработке есть отдельные кнопки «Демо-организатор» и «Демо-участник». Обычная регистрация предлагает выбрать роль. Прежние владельцы событий автоматически получили роль организатора.

Камера использует заднюю камеру телефона и требует HTTPS либо localhost; фотографию QR можно загрузить отдельно. На реальном телефоне нужен доступный ему HTTPS-адрес приложения. Физическая камера телефона в текущей сессии не использовалась: проверены настоящий PNG-код и видеодекодер на синтетическом MediaStream.
