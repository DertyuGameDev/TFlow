# Правила работы с Git

- Перед коммитом и пушем обновляйте текущую ветку из её удалённой ветки. До pull сохраните незакоммиченные изменения; не теряйте чужую локальную работу.
- При конфликтах объединяйте изменения так, чтобы сохранялись новые функции других участников репозитория и текущая реализуемая функция. Не заменяйте целые файлы через `ours` или `theirs`, если это удаляет нужные изменения.
- Актуальная версия формы регистрации — в `origin/main`. При синхронизации не возвращайте её к старому варианту. Менять её поведение или оформление можно по отдельному запросу пользователя.
- В коммит включайте изменения текущей задачи. Несвязанные незавершённые изменения других участников сохраняйте в рабочем каталоге.

Запомни - очень важно чтобы когда ты будешь пуллить или пушить изменения, ты должен брать от нашего коммита ТОЛЬКО то что ты изменил конкретно, в конфликтах тоже именно наше решение но ТОЛЬКО если на него была задача, то есть если мы случайно имезнили профиль, но целью был вообще не он, то взять профиль нужно с гита а профиль уже залить

- При разрешении конфликтов сохраняйте наше решение только в пределах явно поставленной задачи. Для случайных изменений вне задачи используйте актуальную версию удалённой ветки; чужую незавершённую локальную работу предварительно сохраняйте отдельно. Проверяйте отдельные изменения внутри файлов, а не выбирайте целый файл по стороне конфликта.

## Автоматическая выкладка

- Основной источник — GitHub `main`. После проверок отправляйте только изменения текущей задачи туда. Workflow `Verify and package` → `sync-gitlab` переносит новый GitHub-delta в GitLab через проверяемый MR; успешный GitLab CI автоматически запускает `deploy-spirit-cu` на той же VM. Не создавайте параллельные ручные выкладки для того же изменения.
- Push или зелёные unit-тесты сами по себе не завершают задачу: дождитесь успешного `sync-gitlab` и соответствующего `deploy-spirit-cu`. Проверяйте идентификатор через `/api/version` и реальный интерфейс по адресу https://hack-mmk-25-vm1-162f2c.teleport.t-education.com/ .
- При конфликте синхронизация останавливается. Объединяйте только относящиеся к задаче изменения, сохраняйте новые функции команды и не применяйте force push.
- Вкладка с открытой старой сборкой показывает «Доступна новая версия». Не перезагружайте страницу с несохранёнными пользовательскими данными автоматически.
